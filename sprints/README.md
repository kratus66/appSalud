# Sprints del proyecto

Esta carpeta centraliza la documentación funcional y técnica de cada sprint.

## Convención de nombres

- `SPRINT_01.md`
- `SPRINT_02.md`
- `SPRINT_03.md`

Si un sprint requiere una variante más descriptiva, se puede usar:

- `SPRINT_09_AUTENTICACION_Y_AUDITORIA.md`

## Flujo de trabajo

1. Envíame el resumen del sprint o el contexto del trabajo realizado.
2. Yo redacto el archivo Markdown con una estructura consistente.
3. El archivo se guarda en esta carpeta.
4. Si el sprint cambia más adelante, actualizo el mismo archivo.

## Estructura base

Cada sprint debería incluir como mínimo:

- Objetivo
- Alcance
- Cambios en backend
- Cambios en frontend
- Cambios en base de datos
- Archivos o módulos afectados
- Pruebas realizadas
- Incidencias corregidas
- Pendientes

## Recomendación

Mantener un archivo por sprint evita mezclar avances, facilita auditorías y permite reconstruir el historial técnico del proyecto.
